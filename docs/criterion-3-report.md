### Known limitation — load-induced false negatives (non-gating, environmental)
Under pathological host load (observed only at load average ≥~26; absent at ≤12 — these load figures are **session-local, unverified external observations, non-gating**), MIRAI's timeout-bounded analysis can **drop** expected diagnostics — a false *negative*, not a false positive (in default analysis mode; the `--completely-analyze` existential-arm exception is detailed below). Two independent, orthogonal timeouts contribute: the 100 ms per-Z3-query wall-clock timeout (`z3_solver.rs:67`) yielding `SmtResult::Undefined`, and the per-function analysis budget (`BodyTimeout`). This is a global CPU-starvation artifact affecting generic fixtures (e.g. `arc_load_thin_pointer`, `model_field_arc_alias`, `callback_carrier`) and is **not** a soundness gap in the socket-decode gate: the Criterion 3 decode cells route through the pre-solver, deterministic `EncodingIncomplete` path (`body_visitor.rs`, `existential_encoding_is_complete`) and are timeout-invariant by construction — they never regressed under load. A per-query high-timeout re-solve on `Undefined` was implemented and load-tested (@opus); it did **not** eliminate the flakiness (15/20 under synthetic load 26–62 — a **session-local, unverified external measurement with no committed artifact, non-gating**) because it cannot address the orthogonal `BodyTimeout` and can worsen it by consuming the body budget, so it was reverted on canonical (`317806b`). Recorded as a documented environmental limitation, not a Criterion 3 regression. In default analysis mode the direction is dictated by construction (the `--completely-analyze` existential arm is the sole exception, detailed next). There are two `Undefined` match arms, and they must be characterized **separately** (correction per @factchecker, code-verified by @opus): (a) the always-on alias-inference solver arm (`call_visitor.rs:5289`) is `=> continue`, so a timeout there is a pure *drop* of an inferred not-alias precondition — a false negative only, never a spurious note; (b) the existential-precondition check arm (`call_visitor.rs:5443`, `ExistentialPreconditionResult::Undefined`) is reached **only** under `--completely-analyze`/`may_complete` (guard at `call_visitor.rs:5400`, `may_complete && refined_condition.as_bool_if_known().is_none()`). On that arm `Undefined` calls `record_coverage_gap` (an internal `CoverageRecord` pushed into the buffered coverage side-channel consumed via `coverage_for`/`region_gaps`, **not** a compiler warning/note) and then **falls through** to the normal precondition-satisfaction handling. Crucially, that arm's sibling `ExistentialPreconditionResult::UnsatisfiableComplete` does `record_existential_refutation(...); continue` — a proof-of-safety that *suppresses* the diagnostic — whereas `Undefined` does **not** `continue` and can therefore reach `issue_diagnostic_for_call` -> `emit_diagnostic_for_precondition`, which issues a `possible ...` `[MIRAI]` `struct_span_warn` (subject to the promotable-disjunct guard at `block_visitor.rs:2013` and the `contains_top` guard at `call_visitor.rs:5661`). So on this `may_complete`-only existential arm a solver timeout *can* fail to suppress and thereby **add** a spurious note — the "never add a spurious diagnostic note" property holds specifically for the alias-inference branch (5289), not globally. This existential-arm behavior is a documented `--completely-analyze`-only limitation that is **orthogonal to and does not gate Criterion 3**: the socket-decode gate routes through the deterministic pre-solver `EncodingIncomplete` path (above) and never enters this `may_complete` existential block, so its verdict is timeout-invariant by construction. The default-mode alias-inference arm's non-emitting timeout behavior was made explicit by `23d186a` (which separates solver timeout from incomplete encoding while `EncodingIncomplete` still retains the guarded diagnostic; test `complete_boolean_query_distinguishes_incomplete_encoding_from_solver_timeout` is committed in `body_visitor.rs`, though its 30/30-stability run-count is a **session-local, unverified observation with no committed artifact, non-gating**) — so **in default analysis mode** no spurious-note (false-positive) path remains open, and the residual there is exclusively the load-induced false negative described here; the one spurious-note path identified above (the `--completely-analyze` existential arm) is non-gating for Criterion 3.

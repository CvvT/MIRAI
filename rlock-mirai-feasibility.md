# Feasibility Report: Porting **rlock** onto **MIRAI**

## Executive Summary

**Verdict: FEASIBLE WITH SUBSTANTIAL BACKEND WORK / ENCODABLE-WITH-COST — as a constrained MIRAI *fork*, never on stock MIRAI — and contingent on first tightening rlock's own callback handling. Overall confidence: medium-high.**

*Not fatal, not free.* rlock and MIRAI already share the two primitives that matter: both are **rustc drivers over MIR**, and both see RAII **`Drop`** terminators — the raw signal from which a lock-held-set is built. The port is therefore not blocked at the IR or infrastructure level.

The single load-bearing obstacle is a **discipline conflict, not a missing capability.** MIRAI's default engine computes a callee's summary by **analyzing the callee's body on demand** whenever no cached or contract summary exists ([`summaries.rs:33-60`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/summaries.rs#L33-L60); [`call_visitor.rs:103-167`, `:314-418`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/call_visitor.rs#L103-L167)). Callers thus transitively depend on callee bodies — a direct violation of rlock's mandatory read rule: *checking a function reads only its own body (plus lexically-inner closures) and its direct callees' **annotations**, never a callee's body.*

The bridge is real but narrow: the body-derivation happens at `create_and_cache_function_summary` (`call_visitor.rs:377`, within `get_function_summary` `:316-418`), whose result is **cached back** at `:385-394` and returned on later lookups at `:373-374` — so gating it is a **provenance discipline across two points**, not a single branch (see §2.4). A standalone model now proves the required lock-effect semantics are coherent: pairwise non-transitive order edges, receiver-relative resources, removable held-state, unheld-release rejection, and reviewed-contract-only provenance all pass in `checker/src/rlock_prototype.rs` (10/10 focused tests). That closes the prior expressiveness unknown at the model level, but **not** the MIRAI integration question: the prototype is hand-rolled and does not touch the real summary cache, tag domain, abstract-value domain, or `call_visitor.rs`. MIRAI's `foreign_contracts` mechanism is a **candidate** host for promoted/reviewed contracts — a likely reuse point, but not a proven integration path. Taking it means running MIRAI **against the grain** of its defining design — top-down, whole-program, body-derived summaries. And it cuts both ways: **rlock itself is not fully read-rule-compliant today** (its callback path reads local `FnDef` bodies), so a faithful port must tighten rlock before inheriting it.

## Findings

### 2.1 What rlock is *(High confidence — source-verified, `cargo test -q` green)*

- **Driver / IR.** rustc driver in `after_analysis`, iterating `tcx.mir_keys` over **`tcx.optimized_mir`** (`rlock-driver\src\main.rs:356-409`, `:382`, `:408`); lowers MIR into a `LockCfg` preserving `Call`/`Drop`/`SwitchInt`/`Return` (`:1801-1889`).
- **Lock-held-set — prototype exists today.** rlock already recovers a MIR held-set from guard-producing calls, tracked guard transfers/moves, and `Drop` releases (`rlock-check\src\lib.rs:433-457`, `:678-790`). No separate drop-elaboration pass required.
- **Reviewable contracts.** Explicit lock-effect vocabulary — `RequiresNoConflict/Held/NotHeld`, `Acquires/Releases`, ordered edges, callback effects, `OpaqueCall`, `Summary` (`rlock-annotate-lock\src\lib.rs:38-89`) — surfaced as `#[rlock::summary/requires/ensures(...)]` + macros (`lock_extension.rs:69-157`; `rlock-macros\src\lib.rs:8-46`).
- **Modularity — mostly, not fully.** Core direct-callsite path is annotation-only: resolves the direct callee via `func.const_fn_def()`, reads *its annotations*, translates resources to caller args (`main.rs:1437-1573`). **Two confirmed leaks:** (a) pre-check inference scans *all* local MIR bodies (`main.rs:103-131`); (b) callback checking reads local closure **and `FnDef`** bodies via `optimized_mir` (`main.rs:2718-2862`, `:2913-2917`) — the `FnDef` case exceeds "own body + lexical closures."
- **Fail-closed.** Unresolved/bodyless-unannotated calls → `OpaqueCall` (`main.rs:1487-1489`, `:1542-1549`); a live guard over an opaque call warns by default, errors under `RLOCK_STRICT_OPAQUE` (`rlock-check\src\lib.rs:604-623`).
- **Maturity caveat.** rlock has a **working prototype MIR checker** (rustc-driver path), but the **full enforcement/coverage story is incomplete** (README); e.g. `summary(acquires(...))` is parsed/modeled but dropped at `main.rs:1470-1475`. This is "host rlock's contract-checking *discipline* on MIRAI," not "port a finished analyzer." The MIR path itself exists and runs.

### 2.2 What MIRAI provides *(High confidence — local source + public docs)*

- **Driver / IR.** Abstract interpreter over MIR; plugs into rustc post-lowering; functions exchange info via summaries inlined at call sites ([Architecture.md](https://github.com/endorlabs/MIRAI/blob/main/documentation/Architecture.md#L3-L20)). Main body IR is **`tcx.instance_mir`** (const: `mir_for_ctfe`) — **not** `optimized_mir`, which appears only in closure/special cases ([`body_visitor.rs:111-116`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/body_visitor.rs#L111-L116); [`call_visitor.rs:273-275`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/call_visitor.rs#L273-L275)).
- **Drop visibility.** Visits `StorageLive`/`StorageDead`/`Drop` and resolves destructors ([`block_visitor.rs:120-140`, `:477-560`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/block_visitor.rs#L477-L560)). MIRAI exposes enough MIR drop/storage hooks to **host** a guard-liveness pass — it does **not** provide a lock-held-set itself.
- **Summary model — body-derived on demand.** Summaries are declarative caller-used specs, built from the actual body, a contract-function body, or a dummy signature; if no cached/contract summary exists and MIR is available, MIRAI creates a `BodyVisitor` and analyzes the callee body ([`summaries.rs:33-60`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/summaries.rs#L33-L60); [`call_visitor.rs:103-167`, `:314-418`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/call_visitor.rs#L103-L167)).
- **Annotations & contracts.** Generic `precondition!/postcondition!/verify!/assume!`/tag/model-field macros — no-ops outside MIRAI ([`annotations/src/lib.rs`](https://github.com/endorlabs/MIRAI/blob/main/annotations/src/lib.rs)). **`foreign_contracts`** contract functions provide a boundary-summary seam ([Overview.md#foreign-functions](https://github.com/endorlabs/MIRAI/blob/main/documentation/Overview.md); [`utils.rs:377-423`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/utils.rs#L377-L423)). **No native lock-effect grammar** — `acquires`/`requires_no_conflict`/order edges are **net-new**, not pre-existing; found mutex-related `foreign_contracts` are trivial/default models, not held-lock or deadlock-order summaries.
- **Indirect calls.** `Fn/FnMut/FnOnce` resolved via the fn/closure ref then its summary; unknown callees → missing-summary/incomplete cases ([`call_visitor.rs:1229-1395`](https://github.com/endorlabs/MIRAI/blob/main/checker/src/call_visitor.rs#L1229-L1395)); imprecision under indirection acknowledged ([CallGraph.md](https://github.com/endorlabs/MIRAI/blob/main/documentation/CallGraph.md#L17-L55)).

### 2.4 The central tension — split verdict *(the primary feasibility criterion)*

- **Stock MIRAI, unchanged → NO** *(High confidence).* Its normal engine computes missing callee summaries from callee bodies on demand and inlines them — a structural violation of rlock's mandatory read rule.
- **MIRAI as a policy-layer fork → FEASIBLE WITH SUBSTANTIAL BACKEND WORK** *(Medium-High on the modularity bridge; Medium overall).* In `CallVisitor::get_function_summary` (`call_visitor.rs:316-418`), a cache lookup returns early at `:373-374` when `result.is_computed`, otherwise it falls through at `:377` to `create_and_cache_function_summary` (`:106`) → `BodyVisitor` → `visit_body` — the body-derivation call — and **writes the freshly body-derived summary back into the same cache** at `:385-394`. **This is a two-point provenance discipline, not a single clean branch.** `is_computed` conflates three origins (body / contract / dummy) and is **not** a provenance flag: a later `:373-374` hit can return a summary whose provenance is a callee body cached on an earlier visit. A faithful rlock mode therefore cannot gate on `is_computed` alone; it must enforce **provenance-tagged, reviewed-contract-only** summaries across *both* the fall-through (`:377`) **and** the cache-write (`:385-394`) that feeds `:373`. Concretely, either (a) disable the body-derive-and-cache path (`:377` + `:385-394`) and accept only reviewed-contract-provenance summaries, or (b) tag summaries with provenance and make the `:373` check reject body-derived entries. `foreign_contracts` is a **candidate** host (integration unproven); when no reviewed contract exists, return a **fail-closed opaque lock summary** rather than summarizing the body. This boundary policy delivers *both* the read-rule bridge (#4) and the fail-closed policy (#6). The fixed-point machinery is downstream of these points, so disabling body-derivation **likely** degenerates to contract application rather than breaking the engine — but this still needs integration validation in MIRAI's real summary path (see residual uncertainty below). The change is architectural, not a flag, and slightly costlier than a single gate.

**Closure boundary (#7):** the rule permits reading **only lexically-inner closures** of the checked function.
- **Allowed:** inlining a closure defined lexically inside the analyzed function (matches rlock `main.rs:2919-3112` for the lexical subset).
- **Forbidden → narrow or promote:** arbitrary callee bodies and local `FnDef` callbacks.

⚠️ **This cuts both ways — rlock itself is not compliant today** (callback `FnDef`-body reads at `main.rs:2718-2862, 2913-2917`; all-bodies pre-inference at `:103-131`). The port must narrow rlock's callback handling to lexically-inner closures, *or* materialize inferred callback contracts as reviewed annotations before checking — a prerequisite on the **rlock side**, independent of MIRAI *(High confidence)*.

## Conclusion

Porting rlock to MIRAI is **feasible with substantial backend work, as a constrained MIRAI fork — not a drop-in backend** *(medium-high confidence)*.

**Ports cleanly:** MIR ingestion, the rustc-driver harness, and `Drop`-terminator visibility (which *enables*, not *provides*, guard liveness).

**A minimal viable port requires (ordered):**
1. Reuse MIRAI's MIR ingestion + drop-visitor + summary cache + `foreign_contracts` (candidate boundary-contract host, integration unproven).
2. **Build a net-new lock-effect summary layer** (rlock's `LockEffect`/`Mode`/order-graph) atop MIRAI's summary/tag domain — not existing macros.
3. **Bolt on the lock-held-set pass** on MIRAI's `Drop`/storage handling.
4. **Enforce a two-point provenance discipline in `get_function_summary` (`call_visitor.rs:316-418`)**: gate *both* the body-derive call (`create_and_cache_function_summary`, `:377`) *and* the cache-write-back (`:385-394`) that feeds the `:373-374` hit. Accept only provenance-tagged reviewed/promoted contract summaries (`is_computed` alone is insufficient — it conflates body/contract/dummy origins) + fail-closed fallback (bridges read-rule #4 *and* opaque policy #6).
5. **Add a place-identity adapter** (`PlaceRef::canonical_mir` ↔ MIRAI `Path`), reconciling the `optimized_mir`↔`instance_mir` stage delta.
6. **Constrain closure inlining** to lexically-inner closures, and **fix rlock's own `FnDef`-callback + all-bodies leaks** first.

**Primary feasibility criterion — the read rule** — is *satisfiable only after two fixes hold simultaneously*: forcing MIRAI to contract-only boundary resolution, **and** narrowing rlock's own callback-body analysis. Until both hold, the rule is **not** preserved.

**Prototype update (2026-07-06):** the prior expressiveness unknown is now closed at the model level by `checker/src/rlock_prototype.rs` (wired at `checker/src/lib.rs:95`; **10/10 unit tests, verified exit 0**). Its focused model demonstrates the target semantics as a net-new lock-effect domain: explicit `OrderEdge` pairs are **non-transitive** (declare A≺B, B≺C; A→C rejected unless an explicit A≺C edge exists — `pairwise_order_is_not_transitively_closed`); resources are **receiver-relative** (per-value, not per-type); held locks are **removable on release** (which append-only tags provably cannot do, `tag_domain.rs:102`); releasing an unheld resource is rejected; and body-derived, dummy, or missing summaries are rejected in favor of **reviewed-contract provenance**. This is evidence for **ENCODABLE-WITH-COST**, not full ENCODABLE, because the model imports only `BTreeSet` and hand-rolls `SummaryProvenance`/`ReviewedCallee`; it does not wire into MIRAI's real `Summary.is_computed`, summary cache, `call_visitor.rs:373-394`, tag domain, or abstract-value domain. MIRAI has **no reviewed-contract surface for *local* callees** (`foreign_contracts` is non-local only — `is_foreign_contract`, `utils.rs:416`), so the provenance gate is net-new.

**Counter-evidence (load-bearing):** the one artifact that *did* run through MIRAI's real engine — a fixture using stock `precondition!` in a callee body — **failed** the callee-body-mutation oracle (it rode body-derivation via `create_and_cache_function_summary`, `call_visitor.rs:377`) and was removed. That is positive evidence the **naive stock-tag encoding violates the read rule**.

**Verdict: ENCODABLE-WITH-COST — Medium-High (held, not promoted to High)**, because body-independence at MIRAI's *real* boundary is **modeled, not built**. Three named costs (now evidenced, not projected): (1) a **net-new lock-effect domain** (edge-set + removable held-set; stock tags insufficient); (2) a **net-new provenance-gated contract boundary for local callees** (MIRAI has none); (3) **order edges + acquire/release expressed as reviewed contracts**, not `precondition!` bodies (the removed fixture's fatal flaw). **Single step to ENCODABLE (High):** wire the model's provenance gate + edge relation into `call_visitor.rs:373-394` and pass the callee-body-mutation oracle on a **real** fixture — mutate a contract-bearing callee's *body* → caller diagnostic unchanged; delete the *contract* → call under a live held resource fails closed. Scoped engineering increment, not an open feasibility question; the **read rule remains the primary gate and is explicitly the unbuilt residual**.

**Honestly open — the residual uncertainty:** (a) whether MIRAI's fixed-point engine operates correctly with body-derivation disabled — *medium confidence it's separable* (the gated call sits upstream of `join_side_effects`/`widen`), unproven; (b) whether the modeled provenance gate and pairwise edge relation can be wired into MIRAI's actual `get_function_summary` boundary and proven body-independent with a real callee-body-mutation oracle. The expressiveness question is no longer open at the model level; the remaining cost is integration. This integration item, not guard-liveness, is what keeps the verdict at medium-high rather than high. The MIR-stage delta (both expose the `Drop` terminators needed for RAII modeling, so guard-liveness recovery survives, but place/location identity must be reconciled) is a minor adapter concern, not a blocker *(medium-high)*.
